# Groove

A movement-coaching web app run by Greg (gpspicer2), an exercise-science professional, for his clients — friends and family first. The goal is to make his background and ACSM-based guidance accessible: clients log workouts, track ACSM weekly goals, journal privately, and read short tidbits. Greg's own account is the coach ("trainer") view.

## Working with Greg
- Greg isn't a developer. Explain in plain words, one step at a time, no jargon. Say exactly where to tap/click.
- Take initiative on small, obvious consistency fixes without asking (Greg doesn't want back-and-forth over them). When changing one screen, sweep for the same issue elsewhere.
- Give advice and recommendations, not just execution. Apply obvious "intuitive" improvements app-wide; run anything uncertain past him first.
- Push finished changes straight to `main` (that's what goes live). No PRs unless asked.
- Commit as `gpspicer2 <gpspicer2@gmail.com>` — Vercel's Hobby plan won't deploy commits by other authors.
- Verify changes yourself rather than asking him to: `npm run build` before every push (an unescaped apostrophe in a tour string once broke a deploy), and drive the UI when behavior changes.
- Update the app tour (`src/features/onboarding/AppTour.jsx`) whenever a feature it describes changes.

## Design taste
- Colors (all theme tokens, light and dark): each tab has its own (Birdseye green `LIME`, Move teal `SKY`, Journal amber `AMBER`, Learn mauve `VIOLET`). App-wide and onboarding screens (sign-in, consent, health check, tour intro/Account/exit cards, Getting to Know You, fitness assessment) use plum `PLUM`, matching the logo's G — never a tab's color. Text on amber buttons uses `ON_AMBER` (sand text is too faint on amber). Journal uses amber everywhere, not green or teal.
- Compact, consistent, clean. No wasted vertical space, no repeated titles.
- **Title Case everywhere for names and labels** (Greg's rule): buttons, section headings, card titles, row labels, chips, tab/sheet titles, exercise and activity names ("Lifting Preferences", "Injuries and Limits", "Health Check", "Skip for Now"). Small words (and, or, of, to, a, the, in, on, for, with, at, by) stay lowercase except as the first word, and a trailing particle like "In" is capitalized ("About Weighing In"). Full sentences, questions ("Where are we moving today?"), explanations and placeholders keep sentence case. Apply it to every new label.
- Wording: Greg offers "mentorship", never "coaching"; refer to him as Greg rather than "your coach".
- No walls of text anywhere. Short explanations only on demand ((i) popups, one-time swipe tips).
- Merge overlapping content into one place. Favor one-tap shortcuts.
- No stray symbols in labels. Keep forms tidy and unjumbled.
- Logged sets keep a visible, distinct delete control. "Resume workout" stays a link (making it a button is undecided).

## Stack & deploy
- React 18 + Vite + Tailwind v4, Supabase (auth, Postgres, storage), hosted on Vercel; every push to `main` deploys.
- Live app: https://groove-rho.vercel.app (Vercel team Spicer_Apps, project `groove`). Long `groove-xxxx-spicer-apps.vercel.app` URLs are private per-build previews behind a Vercel login — never give those to clients.
- Supabase Auth → URL Configuration: Site URL and Redirect URLs point at the live app (needed for reset/confirm emails).
- `schema.sql` is a reference copy of what was run in Supabase's SQL editor; the app doesn't run it. Schema changes must be run by Greg in the SQL editor — give him the exact SQL and where to paste it.
- `/api/*` are Vercel serverless functions (account deletion uses the service key).

## Decisions and why
- "Log Workout" (not "Start"): open-ended, covers past sessions too.
- Resistance workouts open with an "Aerobic Warm-up" card (the client picks the activity; never assume a treadmill) and a Dynamic Warm-up, both removable. Exercises start collapsed.
- Add buttons at the bottom of a workout sit side by side in one row: Aerobic (Serial only), Resistance (or "Add to Workout" for aerobic/flexibility workouts), Stretch (lifting workouts, and first on the left in a Flexibility workout). "Add to Workout" opens Aerobic / Resistance / Flexibility; Resistance then branches to Single Exercise / Superset exactly like a lifting workout. Open aerobic cards use the same ⋯ menu as lifts; cards ease in with `.groove-ease-in`. Stretching activities (Static Stretching etc.) log just minutes; Yoga keeps the Light/Moderate/Vigorous split because it also counts toward aerobic. The workout progress bar only shows for Suggested workouts, not a Clean slate (remembered per workout in `groove:cleanSlate:<id>`). Combined mode: Serial = blocks back to back (a single Aerobic button at the end, no cardio buttons between exercises); Integrated = aerobic woven between exercises or sets. Between-sets aerobic logs as a set inside the exercise, not its own card; tap a logged burst to edit or remove it, and "Other" logs something different from the one-tap preset.
- "Use bodyweight" is available on every resistance exercise (default on only for pull-ups, dips, chin-ups).
- Weekly goals follow ACSM: aerobic in moderate-equivalent minutes (vigorous counts double), resistance/flexibility in days.
- Calories: ACSM kcal/min = METs × 3.5 × kg ÷ 200. Resistance sets ≈ 2.5 min at 3.5–6.5 METs by lift; aerobic uses per-activity METs scaled by intensity. Estimates only, no load weighting. Shown live, in History, and on Birdseye.
- Movement Library: three intensity buttons (Light/Moderate/Vigorous), each a short list of everyday activities, plus the client's bpm range when resting HR is set. Simplified from a 6-level slider over the full compendium — Greg found that too long. Activities from the 2024 Adult Compendium of Physical Activities (not Greg's old METs.pdf, which is © Wellsource).
- Exercise and activity names typed by hand are Title Case as you type (`titleCaseLive` in `lib/titleCase.js`; use it on any new free-text exercise/activity field).
- Learn categories are a title prefix (`[Benefits]`, `[Strategy]`, `[Adherence]`) rather than a column. Learn titles are always Title Case: `lib/titleCase.js` is applied when a post is added and when titles are shown (so older posts fix themselves); write any new title in Title Case too.
- Journals are author-only: every entry is private, no trainer RLS policy (SQL already run in Supabase). The Journal tab tells clients Greg never sees it and to message him if there's something he should know.
- First run for clients: consent screen → ACSM health screening → tour (gated in `src/App.jsx`). Consent wording lives in `src/features/screening/ConsentScreen.jsx` (first line says "movement mentorship and education"; the chest-pain line is red, not bold); the first point has a "Learn more about Greg" link that opens `GregBio.jsx` (his photo `public/greg.jpg`; also opened from a quiet "Learn more about Greg" link at the bottom of the Groove drawer (the ☰ on Birdseye), and a short bio in his own words: movement vs exercise; edit the text there); bump `CONSENT_VERSION` when it changes (now `2026-10-v5`). Not yet reviewed by a lawyer.
- Health screening follows the ACSM preparticipation algorithm (Riebe et al., 2015): activity status, symptoms, known CV/metabolic/renal disease; symptom-positive people skip the disease question. Logic and wording in `src/features/screening/screening.js`. Results are stored in `profiles.screening` (jsonb); "doctor cleared me" is self-reported. It informs (banner on Birdseye, Account, coach view) but doesn't block logging. An "other conditions" step (hypertension, obesity, etc.) is recorded for future condition-specific guidance.
- Birdseye calendar: a day with workouts and plans shows View/Log another, then a separate "Planned" section with a Log It (or Start Workout, for today) button per plan, so several plans can be cleared quickly. Swipes inside popups must never move the page or open the Groove drawer (SwipeTabs ignores touches from portals). Tapping an empty past day (or today) goes straight to Move with that date chosen; tapping a day that has workouts asks "View workout" or "Log another workout". (The old separate quick-log form was removed.)
- Planned workouts (`planned_workouts` table): tap an empty future day on the Birdseye calendar; a friendly "Plan a workout?" yes/no leads to emoji tiles (no keyboard unless "Something else" or a note) for a vague workout (title + optional notes) or "Add workout details", which runs Move's normal start flow in planning mode (button reads "Save Plan"). Planned days show a gently blinking icon of the plan type (aerobic unless the plan says Resistance/Flexibility/Combined) with a small timer on it (`PlannedMark`, `.groove-plan-blink`, off for reduced-motion); any plan can get full details later via Add/Edit details. Tapping one opens "Planned Workout" with Edit/Delete, and "Start Workout" when it's today (prefills Move; the plan is deleted once the workout starts). Missed plans from the last 14 days stay on the calendar (static icon); tapping one offers "Log It". A simple plan (no details) logs right there in a small sheet (aerobic asks minutes and Light/Moderate/Vigorous; flexibility just confirms). A simple resistance plan asks "Which muscles?" (optional) when planned, and its Start/Log It opens Move with At the Gym, Resistance and those muscles already chosen, so only the goal is left to pick and the plan is used up; a detailed plan opens Move on its date, prefilled, and Birdseye shows a "Planned for yesterday" card. Plans carry a kind and (aerobic) minutes inside `details` (see `src/features/plan/plan.js`). This week's remaining plans show on the Weekly Goals as tentative progress: a dashed, pulsing segment on the bar and a dashed "+N" beside the count (planned aerobic is assumed moderate intensity; Combined counts toward aerobic and resistance).
- The logo's runner takes a burst of strides (about 1.2 s) every 6 seconds while a workout is in progress (`Wordmark` `running` prop, driven by `moveStatus` in ClientApp) and every 10-20 seconds otherwise. The logo is always two layers (`wordmark-still.png`, the logo with the runner erased, plus `wordmark-runner.png`), so it never swaps images or shifts the page; during a burst the runner layer switches instantly (no crossfade: a fade left the old picture's arms visible as ghosts) to a sprite strip of 12 pre-drawn stride frames (`public/runner-sprites.png` and `-dark`, made by `scripts/make-runner-sprites.py`, needs pillow) that CSS flips through (`.gr-sprite`, `@keyframes gr-frames`; no bursts for reduced-motion). The stride is a real run cycle (`leg_pose`/`arm_pose` in the sprite script: knee-drive, reach, support, toe-off, kick-up; arms pump against the legs; frame 0 is exactly the logo's pose). Earlier tries that failed: legs rigidly swapping with arms crossing the chest (a blob at 40 px), and a small jog in place (read as a dance). Three earlier attempts glitched or looked wrong and were dropped: cutting the picture into rigid limb pieces (jagged seams), a bounce-only version (read as bobbing), and a live SVG with CSS-rotated joints; also tried bending the artwork's own pixels (folds over at big limb swings) (a static filler shape poked out as the legs swung, and CSS transforms on SVG parts are risky in Safari). If the logo artwork changes, re-cut `wordmark-still`/`wordmark-runner` (runner = x 204-389), re-fit the pose constants in the sprite script to `wordmark-runner.png` (they were fitted to ~93% overlap) and re-run it.
- The Dynamic Warm-up card ends with a "Finish Warm-up" button (ticks any drills left, closes the card, opens the first exercise). Completing the Dynamic Warm-up (every drill checked) logs a `flexibility` set named "Dynamic Warm-up" (muscle group 'Warm-up', reps = drill count), so it counts toward the weekly flexibility goal and shows the stretch icon on the calendar; unchecking a drill removes it. It's excluded from the exercise/set counts in History summaries.
- Finishing a workout with nothing logged offers to discard it instead (no "0 exercises" entries in History).
- Move history shows 3 workouts, then 5 more per Show More. Each row has a "bullet" icon on the left for its kind (Activity green = aerobic, Dumbbell teal = resistance, PersonStanding red = flexibility; a mixed workout stacks them), same icons as the Birdseye calendar (`historyKinds`). A history row is never more than two lines: a short title (`historyTitle`: at most two items then +N; flexibility shows the activity, not every muscle; location moves to the opened view) and one truncated summary line.
- Baseline intake is optional (prompted from Birdseye, not a gate; the "Finish Setting Up Your Account" card only appears after the first workout is logged, so day one is about moving, not forms); it now also asks bodyweight. The tour is the only first-run step and only counts as done after its final "get to know you" prompt.

- Birdseye top cards: "Planned for today" (one-tap Start Workout; replaces the generic nudge), and a dismissible "Last week" recap (`weekly.js`, `WeekCards.jsx`): workouts, aerobic minutes, kcal, goal chips, milestones (first 150-min week, every 4-week streak, 10/25/50/100/200 workouts). After two straight weeks meeting the aerobic goal it offers a one-tap ~10% raise (capped at ACSM's 300 min). Load progression already lives in `suggestNextWeight`. Real push reminders still need setup (service worker, VAPID keys, scheduled job).
- After Finish Workout a skippable check-in sheet (`CheckInSheet.jsx`) asks effort 1-10 and "Anything hurt or feel off?" (+ optional note). Saved to `workouts.rpe / felt_off / felt_off_note` (silently skipped if those columns aren't in Supabase yet). The coach client list flags "Felt off after a workout" (last 14 days) and each workout in the client's Workouts tab shows effort and the note.
- "Your Fitness" card on Birdseye (`FitnessTrends.jsx`): sparklines + change for VO2max, resting HR, bodyweight (history in `fitness_measurements`, logged via `lib/measurements.js` wherever those are saved) and estimated 1RMs (`estimated_1rms`). Shows "Time to retest" after ~8 weeks. Is the second tab of the Progress card on Birdseye (closed until tapped), always shown: VO2max has a permanent spot with an Estimate/Retest button that opens the guided field tests (`VO2maxEstimator`). The Last week card closes itself after the client leaves Birdseye 3 times (tab swipe or leaving the app).
- Optional Balance goal (ACSM neuromotor work, days/week, off by default; toggle in Weekly Goals edit; hint mentions adults 65+). A session counts when it includes Tai Chi or Balance Training, which are now in Flexibility's activity list (`BALANCE_ACTIVITIES`). Columns `profiles.balance_goal / track_balance_goal` are read separately so Birdseye works without them.
- Condition tips (`screening/conditions.js`, shown as "Tailored to you" on Birdseye): drafted per reported condition from ACSM guidance, but every tip is `reviewed: false` and hidden until Greg approves the wording; then flip that tip's flag.
- ACSM/NSCA layer: goal tiles show NSCA %1RM and rest ranges; lifts show "Aim X-Y lb" when the client has an estimated 1RM for that exercise (`move/oneRm.js`, loose name match); the muscle picker warns (softly, never blocks) about groups trained in the last 48 hours (`move/muscles.js`); Birdseye has a "Muscles This Week" card (each group 2 days/week, push/pull check) and a rest-day nudge after 6 straight training days; "Your Fitness" has "Log a strength or mobility test" (push-ups, plank, 30-sec chair stand, sit-and-reach, waist) stored in `fitness_measurements`. Only chair stand (CDC STEADI) and waist (ACSM/NIH risk) show a norm label; add push-up/plank/sit-and-reach norms once Greg supplies the ACSM tables, rather than guessing.
- Trends (`birdseye/Trends.jsx`, shown inside the Progress card; `embedded` prop drops its own card shell): one metric at a time as a line with filled area, a point per week (8w) or month (6m / 1y), tap anywhere on the chart to read a point. A dashed line is the least-squares trend (current unfinished period left out) with an "Up ~N% per week" / "Holding steady" label, "Best yet" when the latest point is the best, and a dashed goal line on weekly aerobic. Metrics: weight lifted, calories, aerobic (moderate-equivalent minutes), workouts, bodyweight (from `fitness_measurements`), by muscle group (weight or sets), by exercise (top set, estimated max by Epley up to 12 reps, or total lifted). It loads its own data when opened (sets paged 1,000 at a time, since Supabase returns at most 1,000 rows per request; Birdseye's own `workout_sets` read is not paged and could undercount for very active members).
- Opening the app during an active workout (a fresh `groove:liveBackup` under 12 h old) starts on the Move tab instead of Birdseye; ClientApp also asks the database for an unfinished workout started in the last 12 h, so it works without the local backup.
- The workout title + style + location block at the top of a live workout is sticky (only the exercises scroll). SwipeTabs uses `overflow: clip` (not hidden) so sticky works; sticky must be a direct child of the tall wrapper.
- Opening any exercise card in a live workout scrolls it to the top, just under the pinned title (effect on `activeGroupKey` feeds `pendingScrollKey`).
- Deleting asks for a second tap instead of a pop-up (`lib/useArmed.js`: first tap turns the item BRICK red, second tap within ~3.5 s deletes; tapping elsewhere cancels). Used for logged sets, swipe-row trash buttons ("Sure?"), Cancel workout (with nothing logged it cancels at once, no second tap), Delete workout, plans, notes, articles, End Program. Use it for any new delete. Left as pop-ups: close-baseline, doctor-cleared, remove-from-list long press.
- The exercise left open in a live workout is remembered (localStorage `groove:activeGroup:<workoutId>`), so reopening the app opens and scrolls to it.
- A checked-off exercise (the check button next to Log, or all its target sets / any aerobic logged) is tinted green with a ✅ after its name (`isDone`, `DONE_BG`; ticks saved in `groove:doneGroups:<workoutId>`). Reopening a workout underway with nothing open opens the first unfinished exercise after the last finished one.
- Workout progress ("N/M · P%" with a slim green bar) sits on the left of the tally row under the tabs (ClientApp, fed by `moveStatus.done/total` from `ActiveWorkout.onProgress`); exercises complete = ticked or target sets logged (`isGroupDone`). The pinned workout title below is large and extra bold.
- Finishing a workout: check-in sheet (effort, felt off), then a "Write a Post-Movement Reflection" prompt (`JournalPromptSheet`) that jumps to Journal and opens the reflection (ClientApp `journalRequest`). The Post-Movement Reflection is three short screens (mood slider + "How hard was it?" 1-10, what felt good / what was hard, one thing for next time; saved as `structured.mood/effort/wentWell/wasHard/nextTime`; older entries may carry `energy`), headed "After <workout>" and saving `workoutId` / `workoutTitle`. The Journal re-reads the latest workout whenever the tab opens. Older five-question entries (favorite / least favorite movement) still display and edit in their old form.
- Mid-workout progress: a workout started in the last 12 hours and not finished is shown on Birdseye's Weekly Goals as flashing tentative progress (the same dashed pulsing segment and dashed "+N" used for plans) and only counts as done once it is finished.
- Goal celebration (`birdseye/GoalCelebration.jsx`): confetti plus a fading "Weekly goal reached!" message the first time each weekly goal is met, once per goal per week per device (localStorage `groove:goalsDone:<user>:<week>`). Only fires when the latest workout finished within 6 hours, so goals already met earlier are marked quietly. Reduced motion gets the message without confetti. The flexibility icon is `PersonStanding` (a figure with arms out), replacing the stacked-bars icon Greg didn't like.
- Training programs (`src/features/program/`): optional, self-guided. Goal Strength / Hypertrophy (Undulating or Linear) / Fat Loss, plus days a week (2-6). `programs.js` is pure data/math: weekly splits (full body, upper/lower, push/pull/legs; fat loss mixes lifting and cardio days), waves that repeat with a deload week (4 weeks, 7 for linear hypertrophy), and prescriptions (sets x reps, RPE, rest, exercise count; strength has main lifts plus accessories). Stored in `profiles.program` jsonb (SQL at the end of `schema.sql`; until Greg runs it the program lives in localStorage `groove:program:<id>` so nothing breaks). For strength and hypertrophy the days step offers split choices (`SPLIT_OPTIONS` in `programs.js`, best-supported first with tags and info text: twice-a-week frequency has the most support per Schoenfeld 2016/2019; body-part splits are tagged less efficient; stored as `program.split`). Setup sheet: `ProgramSheet.jsx` (also manage/change/end; starting one sets the resistance goal to its lifting days). Move shows a compact `MoveProgramCard` ("<Goal> Program", "N of M this week · lb lifted since the program began" via `useProgramLifted`, next session name with a one-tap Start; tap the card to expand the phase/week, hypertrophy Undulating/Linear and the session's sets and reps), which builds the workout with the program's exercise count/sets/reps; saved as `groove:programSession:<workoutId>` for the banner) or a quiet "Follow a training program (optional)" link; Birdseye shows a slim `ProgramWeekCard` ("Training Program", the week's days with checks, "Next: day · session" and Start; details live in Move). A pure Resistance workout also has the + Aerobic button, and adding cardio upgrades it to Mixed ('Combined') on the spot. A program session being logged shows "In progress" on Birdseye and only counts as done once the workout is finished (a Mixed workout counts for both a lifting and a cardio session). Clean-slate workouts still work, and every lifting workout shows a plain suggestion line (exercises, sets x reps, RPE) from its training style (`STYLE_CONFIG.suggest`) or its program session. Coach member screen shows the program line.
- Programs use the days the member picks (`program.weekdays`, a "Which days will you train?" step in ProgramSheet; none preselected; `hasChosenDays`, `orderedWeekdays`). `programPlans()` lays the remaining sessions onto the Birdseye calendar (today on, next 12 weeks, done ones skipped) as virtual plans with `programSession` set: they show the planned icon, count as tentative progress on Weekly Goals, can't be edited or deleted ("From your training program"), and Start Workout on the day starts the program session. Programs started before this show a "Pick your training days" button on Birdseye until days are chosen.
- A planned workout can be moved: in the Planned Workout popup, "Move to another day" offers the next 7 days plus a date picker. Your own plans just change `planned_for`; a program session is remembered in `program.moves` ({sessionId: date}), which `programPlans` honors (even if the old day has passed); changing or restarting the program clears moves. `normalizeMoves` keeps each week's sessions in order by date, so whichever lifting day comes first is workout A, then B, then C (moving B past C turns the old C day into B).
- Coach "Needs attention": opening a member acknowledges their current flags (`buildAttention` items have a `kind` + `sig`; hidden until the signature changes, e.g. a new felt-off, or a new workout then a new gap). Saved in localStorage `groove:coachAck:<coachId>` and on the member's `profiles.coach_ack` (SQL in `schema.sql`; skipped quietly until Greg runs it), which the morning push (`api/push/daily.js`) also respects.
- Strava sync (see `docs/STRAVA.md`): Account > Settings > Connect Strava connects a member's Strava so Garmin and Apple Watch workouts import automatically (on app open, at most every 10 min, plus Sync now). Server in `api/strava/*` + `api/_lib/strava.js`; imports are deduped by `workouts.external_id`; hand-logged cardio/stretching is replaced by the matching Strava workout, while hand-logged lifting/mixed sessions win over the Strava copy (soft-deleted, restorable), and refresh Birdseye/Move through the `groove:workoutsChanged` event. Strava workouts show in Move's History with an orange left edge and the Strava mark (`StravaMark.jsx`, `workout.fromStrava`), and the title you gave the activity in Strava after the type in italics ("Run - Title"; stored as `{kind:'strava', title}` in `workouts.plan`, refreshed on every sync from the last 30 days). Needs `STRAVA_CLIENT_ID`, `STRAVA_CLIENT_SECRET`, `VITE_STRAVA_ENABLED=true` in Vercel plus the SQL at the end of `schema.sql`. New Strava apps allow one athlete until approved.
- Muscle balance now lives in a dropdown under the Resistance goal row. Suggested resistance workouts end with 1-2 cool-down drills (`generateCooldown`): a stretch (if the Flexibility goal is tracked, brick color) and a balance drill (if Balance is tracked or age 65+, violet). Each card says which goal it counts toward.
- Font: Outfit everywhere (index.html + `fontFamily` strings); replaced Manrope and Space Grotesk, which read as "robotic" to Greg.
- Exercise rows in a live workout have a visible ⋯ button (`SwipeActions` in MoveTab, now a tap menu, not a swipe) that opens a compact two-column bottom sheet (buttons: Swap (pick a muscle, then an exercise, or type your own), Make a Superset, Never Suggest (swap and hide it from suggestions), Edit Settings, Move Up, Move Down, then a full-width Remove (second tap)). It replaced swipe-to-reveal, which fought with swiping between tabs; no row in the app reveals buttons on a swipe any more (Journal entries tap for Edit/Delete; Birdseye goals edit from the pencil). `RevealPills`/`useSingleOpenRow` are unused leftovers. Drag the dots to reorder. The warm-up rows have it too. Collapsed lift/stretch rows show the name with sets×reps underneath. Weight/reps boxes and Log are tall (tired hands); Target/Last/Try is one quiet line under them.
